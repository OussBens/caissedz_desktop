APairing by QR

Each allowed user shows his own QR: the phone signed in with it never sends a password on the Wi-Fi.

sequenceDiagram
  autonumber
  actor U as User on the PC
  participant D as Desktop server (port 8787)
  participant T as Phone CaisseDZ Scan
  U->>D: phone icon → shows HIS QR code
local addresses, port, code valid 10 min, single use
  T->>D: GET /info on every address at once
  D-->>T: the one that answers
  T->>D: POST /appairer {code}
  Note over D: device token created, only its SHA-256 kept,
bound to this user
  D-->>T: device token + session (12 h, sliding)
  loop later
    T->>D: POST /connexion with the device token
    D-->>T: session again (account still active, permission kept)
  end
  • Allowed: the Admin, and roles with the “Mobile app” permission; the role’s modules and permissions apply (purchase price, margin, stores).
  • The Admin sees and revokes every phone; the others only theirs. A phone connected within 5 minutes shows “Connected”.
  • Windows asks to allow the firewall the first time (private networks).

BA sale from the phone

Every write goes through the PC’s own services, with the phone user’s audit context.

flowchart TD
  S([Scan button on the phone]) --> A[GET /caisse/article/code
product, box or pack at the till price]
  A --> P[Phone cart: customer, quantities]
  P --> E{Till session open
for this user?}
  E -- no --> O[Open it from the phone]
  E -- yes --> V
  O --> V["POST /ventes → VenteService.encaisser
ONE transaction on the PC: sale, stock, cash"]
  V --> R[Receipt on the phone
PC screens refreshed]
  • Also from the phone: today’s sales and tickets, stock per store, product creation (quick or AI), quick entry, receipt photos for Smart Scan.
  • No credit and no loyalty points from the phone; refused in read-only.

AAppairage par QR

Chaque utilisateur autorisé affiche son propre QR : le téléphone connecté ainsi n'envoie jamais de mot de passe sur le Wi-Fi.

sequenceDiagram
  autonumber
  actor U as Utilisateur sur le poste
  participant D as Serveur du poste (port 8787)
  participant T as Téléphone CaisseDZ Scan
  U->>D: icône téléphone → affiche SON QR code
adresses locales, port, code valable 10 min, usage unique
  T->>D: GET /info sur toutes les adresses à la fois
  D-->>T: celle qui répond
  T->>D: POST /appairer {code}
  Note over D: jeton d'appareil créé, seule son empreinte SHA-256 gardée,
lié à cet utilisateur
  D-->>T: jeton d'appareil + session (12 h glissantes)
  loop ensuite
    T->>D: POST /connexion avec le jeton d'appareil
    D-->>T: nouvelle session (compte actif, permission gardée)
  end
  • Autorisés : l'Admin, et les rôles qui ont la permission « Application mobile » ; les modules et permissions du rôle s'appliquent (prix d'achat, marge, magasins).
  • L'Admin voit et révoque tous les téléphones ; les autres seulement les leurs. Un téléphone actif depuis moins de 5 minutes affiche « Connecté ».
  • Windows demande d'autoriser le pare-feu la première fois (réseaux privés).

BUne vente depuis le téléphone

Toute écriture passe par les services du poste, avec le contexte d'audit de l'utilisateur du téléphone.

flowchart TD
  S([Bouton scan sur le téléphone]) --> A[GET /caisse/article/code
produit, colis ou pack au prix de la caisse]
  A --> P[Panier du téléphone : client, quantités]
  P --> E{Session de caisse ouverte
pour cet utilisateur ?}
  E -- non --> O[L'ouvrir depuis le téléphone]
  E -- oui --> V
  O --> V["POST /ventes → VenteService.encaisser
UNE transaction sur le poste : vente, stock, caisse"]
  V --> R[Ticket sur le téléphone
écrans du poste rafraîchis]
  • Aussi depuis le téléphone : ventes et tickets du jour, stock par magasin, création de produit (rapide ou IA), entrée rapide, photos de factures pour Smart Scan.
  • Ni crédit ni points de fidélité depuis le téléphone ; refusé en lecture seule.
