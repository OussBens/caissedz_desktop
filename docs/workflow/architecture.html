⛁Where the data lives

Each system owns its data; they exchange codes (PC code, barcodes), never copies of each other’s tables.

StoreHolds
Desktop SQLite (SQLCipher, key from the machine)Everything the shop does: products, stock journal, sales, cash, customers, suppliers, documents, licence key
bens_ds PostgreSQLWebsite content, admins, licences, BENS accounts (phone + password), plans and grants, Smart Scan buckets, catalogue picks
catalog-api MySQL~615 000 products, sections, sales per shop and day, contributions, confirmation votes, Smart Scan scans
Filesbens_ds media (outside the web folders), catalog-api photos (uploads/), desktop backups

🔑Who authenticates how

No secret is ever in a repository: they live in each server’s .env.

Who callsWhatHow it authenticates
Desktopbens_ds /api/app/caissedz-desktop/*Account session token (after sign-up / sign-in), Authorization: Bearer
Desktopcatalog-api /tendance, /smartscan/*Its signed BENS licence: X-Device-Id + X-License-Key
Desktopcatalog-api /rayons, /products/barcodeNone (public, read only)
PhoneDesktop /api/v1/* (port 8787)Device token from the QR pairing (only its SHA-256 is kept)
catalog-apibens_ds /api/rev/* (Smart Scans)REV_SERVER_TOKEN
bens_dscatalog-api /tendance/stats, /admin/*X-Server-Token = REV_SERVER_TOKEN
Dashboardbens_ds /api/admin/*Admin session cookie; licences and catalogue: Owner with two-factor
Catalogue writescatalog-api POST/PUT/DELETE /products…X-API-Key = API_KEY

⇪Deploying

The order that keeps everything working: the servers first, then the PCs.

flowchart TD
  subgraph D1["catalog-api"]
    A1[Commit and push] --> A2["mise run depwin
only committed files that changed"]
    A2 --> A3["Open the dashboard → Catalogue → Maintenance
or admin_rayons.php"]
    A3 --> A4[Update the tables, then re-sort]
  end
  subgraph D2["bens_ds"]
    B1["mise run depwin
builds site + dashboard, uploads"] --> B2[Migrations run on the host]
  end
  subgraph D3["CaisseDZ Desktop"]
    C1[flutter analyze + flutter test] --> C2["flutter build windows --release
installer"]
    C2 --> C3[Shops install the new version]
  end
  A4 --> B1
  B2 --> C1
  • FTP passwords are saved once per repository (encrypted for your Windows user): %USERPROFILE%\.bens\ftp-pass (bens_ds) and catalog-ftp-pass (catalog-api). Run mise run depwin-pass from the matching folder.
  • catalog-api only sends committed files; a deploy that adds tables needs “Update the tables” (dashboard → Catalogue → Maintenance).
  • A new desktop version that uses a new server feature ships after that server is deployed.

⛁Où sont les données

Chaque système garde ses données ; ils échangent des codes (code du poste, codes-barres), jamais des copies de tables.

StockageContient
SQLite du desktop (SQLCipher, clé tirée de la machine)Tout ce que fait la boutique : produits, journal du stock, ventes, caisse, clients, fournisseurs, documents, clé de licence
PostgreSQL de bens_dsContenu du site, admins, licences, comptes BENS (téléphone + mot de passe), formules, Smart Scans, choix de rayons
MySQL de catalog-api~615 000 produits, rayons, ventes par boutique et par jour, contributions, votes de confirmation, scans Smart Scan
FichiersMédias de bens_ds (hors dossiers web), photos de catalog-api (uploads/), sauvegardes du desktop

  • Les mots de passe FTP sont enregistrés une fois par dépôt (chiffrés pour ton utilisateur Windows) : %USERPROFILE%\.bens\ftp-pass (bens_ds) et catalog-ftp-pass (catalog-api). Lancer mise run depwin-pass depuis le bon dossier.
